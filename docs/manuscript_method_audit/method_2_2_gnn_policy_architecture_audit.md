## A. Executive summary

- The final Stage 3 evidence package does not support describing the main result as a single deployed GNN-encoded graph-pointer RL policy. The final claim map states that GNN and graph-pointer diagnostics were explored but remain auxiliary, not primary evidence.
- The earliest true PyTorch graph component in Run26 is a reward model, not a pointer policy: it uses one deposition track per node, a degree-normalized adjacent-track line graph with self-loops, three custom message-passing linear layers, ReLU activations, mean pooling, and Smooth L1 reward regression.
- The Run26 trainable pointer policy is a separate MLP action scorer, not GNN-encoded. It scores each legal track using 10 step/action features, applies a feasibility mask by setting already visited tracks to `-1e9`, and is trained by offline reward-weighted behavior cloning with cross-entropy on teacher sequences.
- Earlier `src.policies.GraphPointerPolicyPrototype` is explicitly a deterministic proxy pointer policy with no teacher validation or RL training. Run06 candidate generation uses that proxy and records `trained_policy_used=False`.
- Later model-update runs, including Run43 through Run73, replace the Run26 PyTorch GNN with an `OrderGraphMLPRegressor` diagnostic and a reward-weighted transition-frequency graph-pointer diagnostic. These are offline diagnostics, not online RL or teacher validation.
- Candidate batches entering Abaqus teacher validation were selected through hybrid active-learning logic: surrogate reward models, GNN/proxy diagnostics, novelty/diversity, uncertainty, local repair, and handoff selection. Teacher validation evaluates selected scan orders, not a deployed online GNN-RL controller.
- The old `rl/train_maskable_ppo.py` Maskable PPO code is a fixed TWI letter-mask/stripe proxy environment with `CnnPolicy`; it is not the Stage 3 deposition-track GNN pointer implementation and should not be used to fill Table 2.3.
- No explicit trainable parameter count or saved checkpoint metadata was found for the Stage 3 GNN reward or graph-pointer models; Table 2.3 should report `NOT_FOUND` for parameter count unless a new reproducibility artifact is created later.

## E. Recommended manuscript wording

We implemented the permutation constraint by treating each deposition track as a discrete action that may be selected exactly once. In the offline graph-pointer prototype, feasibility was enforced by a visited-track mask: previously selected tracks were removed from the legal set or assigned a very large negative logit before the next action was chosen. The audited Stage 3 code does not contain a single deployed GNN-encoded pointer policy. Instead, the graph component was an auxiliary reward regressor over a line graph in which tracks are nodes connected to adjacent tracks with self-loops and degree-normalized aggregation. Node features encoded normalized track index, parity, center/edge distance, visit position, endpoint flags, and local jump context; graph/order statistics were concatenated after mean pooling. A separate MLP pointer-style decoder scored legal tracks from step-local action features and was trained by reward-weighted behavior cloning on teacher-labelled sequences, not by online policy-gradient interaction with Abaqus. Subsequent model-update runs used surrogate regressors, order-graph MLP diagnostics, transition-frequency pointer diagnostics, novelty, uncertainty, and diversity criteria for active candidate selection. Thus, the GNN/pointer machinery should be described as an offline spatial-relational inductive bias and diagnostic/candidate-generation component, while the final teacher-validated evidence should be attributed to surrogate-guided active-learning selection over feasible scan-order permutations.
